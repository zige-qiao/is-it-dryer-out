# Architecture and development

The app is static HTML, CSS and native JavaScript modules. It needs no dependency installation, framework or build step. Serve the repository root over HTTP; `file://` cannot load the module graph reliably. Deploy the root files **and `src/`** together, including when hosting under a repository subdirectory.

The root keeps production entry files, project metadata and compatibility pointers. Root `voice-test.html` and `camera-flash-test.html` redirect to `diagnostics/`, preserving query parameters and fragments without adding a Back-history entry. Their fallback links work without JavaScript. The root Voice investigation file points to the canonical document. Deploy `diagnostics/` too when diagnostic access is needed.

## Source layout

| Location | Responsibility |
| --- | --- |
| `app.js` | Initial state, DOM lookup, feature wiring, startup and page lifecycle |
| `src/config.js` | Defaults, endpoints, storage keys, calculation constants and diagnostic build identity |
| `src/domain/` | Humidity physics, forecast interpolation and ventilation estimates |
| `src/services/` | Browser storage, geocoding and weather requests |
| `src/ui/` | Formatters, recommendation/dashboard rendering, chart, controls, dialogs, location sheet, events and pull-to-refresh |
| `src/voice/` | Pure command parsing and recognition/microphone lifecycle controller |
| `src/camera/` | Camera lifecycle, review drafts, local pixel geometry, units, normalisation and worker analysis |
| `tests/` | Node tests, browser fakes and pre-refactor calculation fixtures |
| `diagnostics/` | Standalone Voice and Camera flash tools; independent of production code |
| `docs/` | Design system, user guide and development records |
| `work/` | Ignored local previews, logs and private evidence; not deployed |
| `docs/voice/` | Current investigation, historical research and supporting analysis |

Domain functions receive readings/settings explicitly and do not access the DOM or mutate app state. Controllers receive state, elements and callbacks through their factory arguments. The optional second argument supplies browser APIs for isolated tests; production uses `globalThis`. Request identifiers, timers and microphone sessions belong to their controller closures.

`src/ui/explanation.js` derives one set of facts for the recommendation overview and More detail disclosure, then renders them without changing plan outcomes. It owns disclosure visibility and focus return while preserving the native open state. Weather state records `outdoorWindAvailable` independently of the numeric airflow fallback so explanatory copy can distinguish missing speed from calm conditions. Neither field is persisted as a new preference.

Cross-feature callbacks are wired in `app.js`, avoiding circular imports. Browser listeners and timers start only during explicit initialisation, not module import. The camera controller and its recognition graph load through a dynamic `import()` on the first camera tap, so they stay out of first paint; the cache tests follow dynamic imports when checking `APP_FILES`. Input-driven renders (rulers, sliders, steppers, typed values) are coalesced to one per animation frame. The root HTML, stylesheet and entry-script paths remain stable; the app icon is `favicon.png`. The standalone `diagnostics/voice-test.html` / `diagnostics/voice-test.js` diagnostic remains independent of production voice code and retains its historical build identity.

Settings reordering shares the dialog gesture guard's private pointer-eligibility callback through `app.js`; a touch stopping momentum cannot arm a hold. The layout controller owns its 300ms touch hold timer, 8px movement threshold and cancellation cleanup. Handles permit native vertical scrolling and pinch zoom. A scoped non-passive `touchmove` listener prevents native panning only after a hold is armed; changing `touch-action` during a gesture would not affect that gesture. Early movement cancels the hold permanently, and active drag edge scrolling remains enabled. Mouse/pen dragging and keyboard move menus retain their existing behaviour. The decorative drag preview is inert, aria-hidden and stripped of identifiers. Measure untransformed row geometry once per drag and adjust for body scroll offsets; move neighbours with transforms without mutating the real order until drop. Edge scrolling gates on hidden movable-row extents, excluding pinned Recommendation and unrelated Settings content. Use 24px edge zones below the actual header and clear of the footer fade, resettable 200ms dwell, a quadratic proximity ramp capped at 160px/second, and clamp to the remaining hidden extent. Position hysteresis is 8px; ease-out settling is 160ms and disabled for reduced motion. Web Animations and preview layers are cancelled and removed when another interaction or sheet lifecycle change interrupts settling.

White sheets keep a stationary flex shell, their existing native `.sheet-body` scroller and optional opaque footer. `src/ui/sheet-chrome.js` privately enhances browsers supporting both backdrop blur and `scrollbar-width: none`: the body extends behind the header, measured header height compensates its top padding, and the header itself uses a 55%-opaque tint derived from its own sheet surface and standard/Safari-prefixed graduated blur. Use color-mix with explicit warm-grey Settings and white-sheet RGBA fallbacks; the pill keeps its independent white tint. The initial title-to-content gap remains 16px; focus scroll padding clears the overlaid header plus 20px. A full-width 16px tint fade extends below each header without changing content spacing. All five sheets use four decorative, non-interactive masked backdrop layers (4px, 2px, 1px and 0.5px), with overlapping fade windows over the 16px extension so blur strength reduces towards the body; the 55% tint fades separately and the scrollbar is painted above the frosting. Clip each enhanced sheet to its rounded shell to establish a backdrop boundary: the header blurs content within the sheet, never the page behind it; browsers without mask support retain the tint-only fade. A decorative, aria-hidden 4px scrollbar starts 4px below the header and ends 4px above the body bottom, with a 24px minimum thumb. It maps the full native scroll range using the unobscured viewport height. The native scrollbar is hidden only after initialisation. Mouse thumb dragging and track paging target the existing body; touch, wheel and keyboard scrolling stay native. The labelled body region is keyboard-focusable. One queued animation frame batches scroll, resize and content changes; dismissal, interruption and backgrounding cancel pending work and capture. Unsupported browsers retain the original opaque header and native scrollbar below it; forced colours use system surfaces and native scrollbars. Footers retain their opaque surface and 16px fade; Indoor hides its footer in voice/camera modes. Dialog viewport tracking observes editable focus and actual viewport reduction to remove only bottom safe-area padding, ignoring pinch zoom and restoring prior styles on release. Help sizing clears visible footers. Keep this module in the offline cache graph.

The dialog helpers own opener-focus snapshots and synchronous focus return. Sheet activation records whether the opener had visible keyboard focus; dismissal prepares its styling before native focus restoration, then consumes the saved return target so a queued close event cannot overwrite later keyboard interaction. Timer initialisation precedes shared event binding so Escape dismisses its open help popup before the sheet. Start completes dismissal and scroll cleanup synchronously before the Shortcut URL handoff.

## Run locally

The shared document-level gesture activation guard is installed once alongside focus tracking in `src/ui/dialogs.js`. It observes all pointer movement and captured nested scroll events, suppresses compatibility clicks after movement/cancellation, and protects touches that stop actual scrolling. It leaves native scrolling and component pointer handlers intact; keyboard and assistive click activation bypass the pointer guard. Test both directions and a fresh tap after cancellation when adding interactive controls.

The camera loader is shared by the sheet camera entry and Indoor summary camera shortcut, with controller wiring owned by `app.js`. Page layout preferences are normalised by `src/ui/page-layout.js`; its controller moves existing section nodes and owns Settings drag/keyboard ordering, a shared nonmodal text menu, pointer tap/drag discrimination and viewport-safe menu placement. On Overview, Recommendation is always visible and pinned first, followed by hidden Indoor summary and shown Moisture comparison and Chart key by default; saved relative order and visibility of the three optional sections are preserved. Pull-to-refresh derives following nodes from Overview’s order and uses a private overlay lock; chart touch handlers defer inspection until gesture direction is known. The shell stays concealed until initial preferences have been applied so its first visible paint uses the saved order and visibility. The camera loader keeps module availability separate from pending activation: closing Indoor readings, backgrounding/page exit or starting voice cancels the pending tap. Successful loading is retained without activating an obsolete request. The entry button shows a reduced-motion-aware busy spinner during loading; failures restore it and show an inline status above the manual controls. Retry clears failed loading state. Before native import, parallel resource checks warm the HTTP cache and keep ordinary download failures out of the browser module map, which can remember failed imports for the page session. A graph-coverage test maintains this camera-only resource list; creation of the recognition worker stays deferred. Controller initialisation rolls back listeners and label observers on failure, and repeated successful initialisation does not bind them again.

Use an existing static HTTP server rooted at this directory. For example, if Python is installed:

```sh
python -m http.server 8766 --bind 127.0.0.1
```

Open `http://127.0.0.1:8766/`. The server must serve `.js` files with a JavaScript MIME type. Reload after source edits. Live weather and location search require a network connection.

## Verification

`current-row.js` establishes aligned integer-cell scale from raw greyscale strokes before accepting any decoded value or unit. `row-context.js` preserves that rectified LCD frame through overview, original-resolution crops, corrections, worker progress and merging. Every integer cell must meet 80% of the established main height and overlap the current row by at least 50% of its own height. Fractions use separate full-cell validation. Manual selections retain whole-display context while limiting assignment to the selected digits. A later larger reference withdraws smaller provisional candidates; unreadable main digits do not authorize historical replacements. Relative measurements remain local to one LCD, including supported perspective transforms.

Use Node.js 24 or later; CommonJS test files use its native `require()` support for synchronous ES modules.

```sh
node --check app.js
node --check service-worker.js
node --test tests/*.test.cjs
```

`npm test` is an optional shorthand. Where test-worker creation is restricted, run `node --test --test-isolation=none tests/*.test.cjs`. No package installation or lockfile is needed.

Tests import the production functions and controller factories rather than extracting function source. Shared browser fakes live under `tests/helpers/`. The standalone diagnostic still runs its entire script in a VM sandbox. Calculation fixtures preserve outputs captured from the pre-refactor implementation; do not regenerate them just to make a changed formula pass.

The cache tests verify local imports, cycles, module loading without browser side effects, complete precaching, root/subdirectory paths, offline resource failures and activation cleanup. Also smoke-test the actual browser: initial Indoor sheet, chart inspection/range switch, location recovery, preferences, refresh and dialogs at mobile and desktop widths. Mocked media tests cannot establish real iPhone audio capture or microphone-indicator behaviour; use the [voice investigation](voice/VOICE-INVESTIGATION.md) for device verification.
